# ドキュメントの概要

## 目的

このドキュメント群は、ヤマハ YM2608 (OPNA) について次の 2 つを記録する。

1. **公式アプリケーションマニュアルからは読み取れない実機仕様。**
   マニュアルに書かれていない挙動、書かれていても実機と食い違う挙動、書かれてはいるが
   そのままでは正しく実装できない記述を、実機の観測結果として残す。
2. **エミュレータ [ymfm](https://github.com/aaronsgiles/ymfm) と実機仕様の差分。**
   差分そのものと、その差分がどのハードウェア構造の欠落から生じているかを整理し、
   ymfm 側の設計方針の範囲内で採れる精度向上の方向を提案する。

対象は **ADPCM-B (DELTA-T) 音源部**、とくに次の 3 領域である。

- データレジスタ `$08` を経由した外部メモリの read / write
- START / STOP / LIMIT アドレスの設定とメモリアクセスの関係
- ステータスフラグ (EOS / BRDY / ZERO / PCM BUSY / BUSY)

FM 音源部・SSG 音源部・リズム音源部は対象外である。ADPCM-B のうち音声分析 (エンコード) と
AD/DA 変換の経路も、基準となる観測データが得られていないため対象外とする。

想定する読者は、YM2608 のエミュレータ実装者と、実機向けドライバの開発者である。

## 記載内容の根拠

本ドキュメントに書かれている実機仕様は、次の 3 つを突き合わせて得たものである。

| 根拠 | 内容 |
|---|---|
| **実機の測定** | YM2608 実チップに対するレジスタアクセスのログと、ロジックアナライザによる外部バス・ステータスバスの観測 |
| **`YM2608_LLE` での挙動調査** | 回路レベルで YM2608 を再現した低レベル実装 [YM2608_LLE](https://github.com/nukeykt/YM2608-LLE) を直接駆動し、実機では観測できない内部構造と、実機ログの無い設定領域を調べたもの |
| **一次資料** | ヤマハ株式会社「YM2608 OPNA アプリケーションマニュアル」(全 67 ページ) |

実機ログで裏が取れる範囲について、`YM2608_LLE` は実機と一致することを確認済みである
(21 種類の実機測定シナリオすべてで、転送データ列・EOS/BRDY・レジスタ発行列が完全に一致した。
唯一の例外は後述する STATUS1 の D6 で、これは `YM2608_LLE` と ymfm の双方が実機と食い違う)。

したがって**以降の各ドキュメントでは、`YM2608_LLE` から得た観測も実機の挙動として記述する。**
`YM2608_LLE` の名前が出てくるのはこのページだけである。ただし、実機ログで直接裏付けられた事実と
そうでない事実は、次のラベルで区別する。

## 根拠ラベル

| ラベル | 意味 |
|---|---|
| **[実測]** | 実機のレジスタアクセスログ、またはロジックアナライザ観測から直接読めるもの |
| **[解析]** | 回路レベルの解析モデルを駆動して得た実測。**実機ログによる裏取りが無い設定領域を含む** |
| **[推定]** | 観測された事実からの推論。実機でも解析モデルでも直接は観測していない |
| **[未確定]** | 判定できていないもの。どちらの可能性も残る |

**[実測] と [解析] のどちらも「実際に動かして数値を採った」結果**であり、机上の推測ではない。
両者の違いは、観測対象が実チップかその解析モデルかという点だけである。
[推定] と [未確定] は本文でも明示的にそう書く。

## 実機観測の限界

[実測] の粒度は、測定系の構成そのもので決まっている。以下の制約を理解した上で読むこと。

- 実機へのレジスタアクセスはシリアル回線経由のホスト制御で行っており、
  **1 レジスタアクセスあたり中央値 79.8〜79.9ms、ジッタは数十 ms** ある。
  「レジスタを書いてから N ミリ秒後に別のレジスタを読む」といった時間制御はできない。
- ステータスフラグの連続監視は、実機側でポーリングループを回している区間だけ可能である。
  **ポーリングしていない区間のフラグ変化は観測できない。**
- ロジックアナライザが拾っているのは、チップセレクト・データバスの一部ビット・メモリイネーブル・
  DAC 出力である。**アドレスバスは観測していない。**
  したがって外部メモリアクセスは「回数」と「周期」は分かるが、
  **「どの番地をフェッチしたか」は直接には分からない**。

「フェッチ回数が変わらない」といった [実測] の主張が、なぜ特定の仮説を否定しきれないのか
という議論は、この制約から来ている ([09_open-questions.md](09_open-questions.md))。

## ymfm との比較の基準

差分の記述 ([08_ymfm-differences.md](08_ymfm-differences.md)) は、
**`aaronsgiles/ymfm` の `adpcm-test` ブランチ (`37d0112`) を基準**にしている。

このブランチは `main` (`17decfa`) より 11 コミット古い `3d5471f` から分岐しており、
ADPCM-B のメモリ read/write・アドレス・フラグ挙動を実機解析に合わせ込む改良が積まれている。
つまり **`main` ブランチの ymfm は、本ドキュメントが挙げる差分よりさらに実機から離れている。**
`main` を基準に読む場合は、ここに挙げた差分に加えて `adpcm-test` の改良分も差分として数える必要がある。

## カバレッジの注意

**実機ログが存在するのは 8bit DRAM (`$01` の RAMTYPE=1) の範囲だけである。**
1bit DRAM・ROM・および無効なメモリ種別指定については、構造から導かれる結論を [解析] で
確認しているが、それが実チップと一致することは未確認である。
該当する箇所には [解析] ラベルを付けてある。
