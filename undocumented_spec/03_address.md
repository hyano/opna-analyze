# START / STOP / LIMIT アドレスとメモリアクセスの実機仕様

ADPCM-B の外部メモリアドレスは、3 つのレジスタ対 (START / STOP / LIMIT) と、
それを比較するアドレスカウンタで決まる。ここではその実機仕様をまとめる。

構造の前提は [02_internals.md](02_internals.md) の §4 (アドレスカウンタ) と
§5 (マイクロシーケンサ)。根拠ラベルの意味は [01_overview.md](01_overview.md) を参照。

---

## 1. アドレスのビット構成 (マニュアル p.48)

```
| BANK (3bit) | CAS ADDRESS (A8..A0) | RAS ADDRESS (A8..A0) |   計 21bit
```

**16bit のレジスタ値がアドレスの上位 16bit に入り、下位 5bit は固定値で埋まる。**

| | 上位 16bit | 下位 5bit |
|---|---|---|
| START ADDRESS (`$03`, `$02`) | レジスタ値 | `0 0 0 0 0` |
| STOP ADDRESS (`$05`, `$04`) | レジスタ値 | `1 1 1 1 1` |

STOP は「その 32 単位ブロックの**最終要素**」を指す。したがって
START = STOP = `0x0000` と設定すると、1 ブロック (32 単位) が転送範囲になる。

ROM / ×8bit アクセス時は、BANK (D7-D5) を START と STOP で同じ値にする必要がある。

## 2. 分解能

| メモリ種別 | アクセス単位 | 最小分解能 |
|---|---|---|
| DRAM 256k×1bit | **bit** | 32bit = **4 byte** |
| ROM / DRAM ×8bit | **byte** | **32 byte** |

下位 5bit を固定値で埋める点はどちらも同じで、違うのは 1 単位が bit か byte かだけである。
バイトアドレスに直すと ×1bit DRAM は `レジスタ値 << 2`、ROM / ×8bit DRAM は `レジスタ値 << 5`。

**×1bit DRAM のビット単位アドレッシングは実際にそう動く** [解析]。
1 バイトあたり RAS / CAS / WE が 8 回発生し、アドレスカウンタは 1 アクセスごとに 1 増える
(ビットアドレスを直進、LSB first)。ダミーリード 2 回・末尾で BRDY が立たないという構造は
×8bit DRAM とまったく同じである。

## 3. 実効アドレス幅は 21bit

STOP / LIMIT の一致判定は 3 フェーズ (9 + 9 + 3bit) で完結するので、
**実効アドレス幅は 21bit (アクセス単位)** である [解析]。バイトアドレスに直すと:

| メモリ種別 | カウンタの単位 | バイトアドレス幅 |
|---|---|---|
| ROM / ×8bit DRAM | byte | **21bit** (`0x1FFFFF`) |
| ×1bit DRAM | bit | **18bit** (`0x3FFFF`) |

`(1 << (16 + シフト量)) - 1` と表せる (シフト量は 5 または 2)。
レジスタ最大値 (バイトアドレス `0x1FFFFF`、21bit の最上位) を設定しても、
アドレス `0x0000` と同じダミーリード / EOS のパターンになることを確認している [解析]。

## 4. STOP は保持ラッチ、LIMIT は瞬時判定

**この非対称が、STOP と LIMIT の挙動の違いをすべて生んでいる。**

### STOP

STOP の一致は**保持ラッチ**に記録される [解析]。

- **解除されるのは START アドレスをロードするときだけ。**
  時間が経っても、他のレジスタを書いても解除されない。
- **RESET ビット (`$00` D0) と IC (パワーオンリセット) は、このラッチを強制的にセットする。**
  つまりリセット直後のチップは「終端に居る」状態から始まり、次のアクセスは必ず
  START アドレスのロードを伴う。マニュアル p.46 の「RESET は音声合成を停止して
  初期状態に戻します」と整合する。
- ラッチが立つと、シーケンサのループ分岐がすべてアイドルへ落ちる。
  これが「メモリサイクルの停止」と「BRDY が 0 に張り付く」を同時に起こす
  ([04_data-register.md](04_data-register.md))。

### LIMIT

LIMIT の一致は**保持されない** [解析]。一致している間だけアドレスカウンタの更新をゲートし、
更新されなかった結果として 0 が流れ込む。これが「0 番地へのラップ」の実体である。

### 帰結

- **STOP も LIMIT も、大小比較ではなく一致比較である** [実測]。
  設定値を通り過ぎてしまうと二度と一致しない。
- **LIMIT 到達で戻るのは 0 番地であって START ではない** [実測]。
  マニュアル p.50 の記述どおりだが、START へ戻ると誤解されやすいので明示しておく。
- **LIMIT < STOP という違反設定では、STOP に到達せず EOS も立たないまま回り続ける** [解析]。
  LIMIT で 0 に戻るため STOP のアドレスを踏むことがない。
- **STOP と LIMIT が同値なら STOP が先に効く** [実測]。
  STOP ヒットでは START へ戻ってダミーリードが再発生し、
  LIMIT ヒットでは 0 番地へ戻ってダミーリードは挟まらない。
  構造上も、STOP 側でシーケンサがアイドルへ落ちるため、0 化されたカウンタは使われない。

## 5. 判定はメモリ読み出しのタイミングで起きる

STOP / LIMIT の判定は、CPU が `$08` にアクセスした瞬間ではなく、
**外部メモリからの読み出しが実際に走るタイミング**で行われる [実測]。

読み出しの途中で STOP / LIMIT レジスタを書き換えた場合:

- **ダミーリードを含めて 32 バイト目の読み出しより前**に書き換えれば、次のブロック境界に間に合う
- **それ以降**だと間に合わず、次の境界には旧値が使われる

31 バイト読んだところで書き換えれば有効、32 バイト以降だと無効、という境界は
STOP と LIMIT で同じである。

## 6. START アドレスのロードは最初のアクセス時

**START アドレスがカウンタへロードされるのは `$00` へ書き込んだ時ではなく、
最初のアクセスが始まる時である** [解析]。

- CPU メモリアクセスモードでは、**最初の `$08` アクセス**
- 再生では、**再生のディスパッチが成立した時**

これは [02_internals.md](02_internals.md) §5 の「ディスパッチはアイドルからしか起きない」の
直接の帰結である。実用上は次を意味する。

> **`$00` を書いた後に START / STOP レジスタを書き換えても間に合う。**

なお START ビットは、レジスタ書き込みからモード判定に効くまで内部で 2 段のラッチを通るため、
わずかな遅延がある [解析]。

## 7. メモリ種別と粒度は非対称に効く

**これは本ドキュメント群で最も見落とされやすい仕様である。**

アドレスカウンタの歩進頻度を決めているのは **RAMTYPE (`$01` D1) だけ**で、
ROM ビット (`$01` D0) は関与しない [解析]。

- RAMTYPE = 0 → 1 バイトあたり 8 アクセス、カウンタは**ビットアドレス**
- RAMTYPE = 1 → 1 バイトあたり 1 アクセス、カウンタは**バイトアドレス**

一方、**読み出しのディスパッチは ROM ビットを見る**。書き込みはメモリ種別によらず
同じバンクに入り、ビット単位ループに入るかどうかは RAMTYPE だけで決まる。結果:

| `$01` D1/D0 | メモリ種別 | 読み | 書き |
|---|---|---|---|
| `00` | ×1bit DRAM | bit 単位 | bit 単位 |
| `01` | ROM | **byte 単位** | **bit 単位** |
| `10` | ×8bit DRAM | byte 単位 | byte 単位 |
| `11` | (ROM + ×8bit) | **経路なし** | byte 単位 |

つまり:

- **ROM を指定した状態での書き込みは bit 単位になる。**
  ROM への書き込み自体は実機では無意味だが、`$08` へ書けばチップは 1 バイトあたり
  8 回の WE パルスを出す [解析]。
- **`11` (ROM かつ RAMTYPE=1) は読み出し・再生のどの経路にも当たらず、
  外部メモリに一切アクセスしない。** 書き込みだけは byte 単位で通常どおり動く [解析]。

マニュアル p.53 / p.54 の手順表が `$01` に挙げるのは書き込み側 `$00` / `$02`、
読み出し側 `$40`〜`$42` だけで、**`$03` を挙げる手順表は 1 つも無い**。
マニュアル側もこの設定を定義していないと読める。

### CPU から見える裏取り [解析]

上の結論は、外部ピンの観測だけでなく **CPU から見える EOS の位置と外部アクセス回数**だけでも
確認できる。START = STOP = `0x0000` にして `$08` へ書き続け、EOS が最初に立つバイト数を測ると:

| `$01` | メモリ種別 | ブロック長 | 意味 |
|---|---|---|---|
| `$02` | ×8bit DRAM | **32 byte** | 1 アクセス / バイト |
| `$00` | ×1bit DRAM | **4 byte** | 8 アクセス / バイト (32bit = 4byte) |
| `$01` | ROM | **4 byte** | **×1bit DRAM と完全に同じ。書きの粒度に ROM ビットは効かない** |
| `$03` | (無効) | **32 byte** | RAMTYPE=1 なので**書きだけは通常どおり動く** |

再生側も `$08` の読み出しと同じゲートを通る。ΔN 最大で一定時間走らせたときの
外部フェッチ回数は:

| `$01` | 再生中のフェッチ | ステータス |
|---|---|---|
| `$02` ×8bit DRAM | 140 回 | `0x28` (PCM BUSY + BRDY) |
| `$01` ROM | 140 回 (使うピンが変わるだけで回数は同じ) | `0x28` |
| `$03` (無効) | **0 回** | `0x28` |

**無効な組み合わせでは、START ビットは受け付けられて PCM BUSY も立つが、
外部メモリアクセスが一度も起きず EOS も永久に立たない。**
デコーダは来ないバイトを待ったまま止まる。

## 8. REPEAT

REPEAT (`$00` D4) を立てると、STOP 到達で **START アドレスへ**戻って繰り返す [解析]。
0 番地へ戻る LIMIT とは戻り先が違う。

- **再開位置は START アドレスである** [解析]。
  START ≠ 0 に設定し、0 番地側と START 側に別々の印を置いて 4 ループ回すと、
  毎ループ最初のニブルは START 側の印になり、0 番地側の印は一度も現れない。
- **デコーダの内部状態は毎ループ完全にリセットされる** [解析]。
  4 ループとも、ループ先頭でのデコーダレジスタは初期値そのもので、
  ループ終端の値からきれいに初期化されている。
  これは DSP シーケンサの起動プロローグが**新規 START と REPEAT の再始動を区別しない**ためである。
- **EOS は立てたまま保持され、自動クリアはされない** [実測]。
  詳細は [06_status-flags.md](06_status-flags.md)。
- **CPU メモリアクセス時の REPEAT では、折り返しのダミーリードが 1 回になる** [実測]。
  REPEAT=0 で START へ戻る場合はダミーリードが 2 回挟まるのに対し、
  REPEAT=1 (`$00 = $30`) では 1 回しか挟まらない。
  先読み 2 段のうち 1 段が折り返しをまたいで生き残る、という読み方になる。

### REPEAT=1 のまま `$08` へ書き込んではいけない

**REPEAT=1 のまま `$08` へ書き込むと、STOP 到達後にメモリへ書けなくなる** [実測]。

- 外部メモリのイネーブルは出続けるが、実際には書き込まれない
- ダミーリードには値が残る
- **RESET (`$00` D0) を入れるまで回復しない**
- EOS も 32 バイト目ではなく 63 バイト目で立つ

原因は構造にある。**REPEAT の折り返しは、書き込み中であっても常に読み出しバンクで
再ディスパッチされる** [解析]。読み出しバンクには WE をアサートする段が無いので、
以後の `$08` write はメモリに届かない。そしてバンクはアイドルではないため再ディスパッチもできず、
RESET でしか抜けられない。「書き込みが壊れる」のは特別な故障ではなく、
**読み出しバンクに居座って WE が出なくなるだけ**である。

> **REPEAT は再生専用の機能と考えること。** メモリ書き込みでは使ってはいけない。
> マニュアル p.46 も「RESET, REPEAT は、外部メモリーをアクセス時のみ働く機能です」と
> 書いているが、書き込み時に立てた場合にどうなるかまでは触れていない。
