# ステータスフラグ (EOS / BRDY / ZERO / PCM BUSY / BUSY) の実機仕様

ステータスレジスタの各フラグについて、**いつ立ち、いつ落ち、いつ落ちないか**をまとめる。

マニュアル p.51-52 の記述との食い違いが集中している領域である。
とくに **PCM BUSY**・**BRDY**・**STATUS1 の D6**・**マスクの意味**の 4 点は、
マニュアルどおりに実装すると実機と合わない。

根拠ラベルの意味は [01_overview.md](01_overview.md) を参照。

---

## 1. 仕様 (マニュアル p.51-52)

### STATUS0 (A1=0, A0=0) — YM2203 互換

| bit | 名称 | 条件 |
|---|---|---|
| D7 | BUSY | データをレジスタにロード中。**FM 音源部のレジスタにのみ有効**と書かれている |
| D1 | FLAG B | タイマー B 経過 |
| D0 | FLAG A | タイマー A 経過 |

### STATUS1 (A1=1, A0=0)

| bit | 名称 | 条件 (原文) |
|---|---|---|
| D7 | BUSY | STATUS0 と同一 |
| D6 | — | 未使用 (常に 0) |
| D5 | PCM BUSY | ADPCM 音声/合成の**実行中** "1" |
| D4 | ZERO | ADPCM 音声分析中、290msec 以上、**無音状態が続く時** "1" |
| D3 | BRDY | 分析(合成)時: 2 データ (4bit×2) の終了時。外部メモリライト(リード)時: 1 データの終了時 |
| D2 | EOS | ADPCM 音声分析/合成の終了時、AD/DA 変換時の 1 サンプリング周期の経過時 |
| D1 / D0 | FLAG B/A | タイマー |

### FLAG コントロール `$10` (p.51)

| bit | 機能 |
|---|---|
| D7 | IRQ RESET。"1" で書くと D4-D0 のマスクビットは無視され (書き換えられず)、同時にステータスフラグを "0" にする |
| D4-D0 | MASK ZERO / MASK BRDY / MASK EOS / MASK TIMERB / MASK TIMERA。"1" でそのフラグを**発生させない** |

**リセット後の初期値は `0x1C`** (D4, D3, D2 = 1) である。
つまり**電源投入直後は ZERO / BRDY / EOS がマスクされた状態から始まる。**

## 2. マスクは「隠す」ではなく「破壊する」 [解析]

マニュアルの「発生させない」という表現は正確で、**マスクはレベル信号として
フラグを 0 に固定し続ける**。読み出し時に隠すのではない。

```
マスクが真の間、フラグは 0 に固定され続ける
```

帰結:

- **マスクを立てる → イベント発生 → マスクを外す**、の順でもフラグは見えない。
  イベントは発生時点で失われている。
- **マスクを外している間に発生 → その後マスクを立てる**、でもフラグは即座に破壊される。

タイマ TA / TB も同じ意味論である。

> エミュレータが「読み出しのときだけマスクする」実装になっていると、
> マスク解除後にフラグが顔を出してしまい実機と食い違う
> ([08_ymfm-differences.md](08_ymfm-differences.md))。

### `$10` D7 (IRQ RESET) がクリアする対象 [解析]

**TA / TB / EOS / BRDY / ZERO のみ。**
**PCM BUSY と BUSY はクリアされない** (別系統のため)。

また D7=1 で書いたときは、**D4-D0 のマスクビットは更新されない**。

## 3. PCM BUSY は実質「START ビットの読み返し」 [実測]

**マニュアルの記述からの最大の乖離がここにある。**

PCM BUSY (STATUS1 D5) は、`$00` の D7 (START ビット) をラッチしただけの値である。
START ビットの値が変わる契機は **`$00` への書き込み**と **IC** の 2 つしかない。したがって:

> **PCM BUSY は EOS でも RESET ビット (`$00` D0) でも落ちない。**

「PCM BUSY が落ちるのを待つ」という制御は実機では**永久に返ってこない**。
再生の終了を知るには **EOS を見る必要がある。**

実測された時系列 (32 バイトブロック、`$A0`、ΔN 最大):

| 時点 | STATUS1 | 内訳 |
|---|---|---|
| 再生開始直後 | `0xA8` | BUSY + PCM BUSY + BRDY |
| 1 ニブル供給後 | `0x28` | BUSY は `$00` 書き込み由来のワンショットなのですぐ落ちる |
| 再生終端 | `0x2C` | **EOS が立つ** |
| その後いくら待っても | `0x2C` | **PCM BUSY は落ちない** |

### 検証時の落とし穴

> **`$00 = $01` で RESET ビットを検証してはいけない。**
>
> `$00` への書き込みでは**そのバイトの D7 がそのまま START ビットになる**ため、
> `$00 = $01` は RESET (D0=1) と同時に **START も 0 にしてしまう**。
> これで試すと PCM BUSY が落ちてしまい、上の結論を誤って反証することになる。
>
> START を 1 に保ったまま RESET だけを立てる **`$00 = $81`** で追試すること。
> このときニブルの供給は即座に停止する (RESET がシーケンサを強制的にアイドルへ落とすため) が、
> **EOS は立たず PCM BUSY も 1 のまま**である。

## 4. BRDY はレベル信号 [実測]

BRDY は「レディである」という**状態**を表すレベル信号であって、イベントパルスではない。
`$10` D7 でクリアしても、レディであれば即座に立ち戻る。

**レベルであることは実機で直接見えている。**
`$00` の REC / MEMDATA が転送経路のどれにも当たらない設定
(REC=1 で read、REC=0 で write) では、実機は **2 バイト目以降 BRDY=0 のまま張り付き**、
EOS も立たない ([04_data-register.md](04_data-register.md) §6)。
イベントラッチなら「一度立って消える」になるはずのところが、
「そもそも立たない状態が続く」になっている。

張り付きの実体は、**メモリサイクルが一度も完了しないのでレディが戻らない**ことである。

### 再生中の BRDY

**メモリ駆動再生中の BRDY は常時 1 に張り付く** [実測]。
開始から EOS 後まで一度も 0 にならない。ただし **CPU が `$08` に触れると落ちる**
(`0x28` → 以後 `0x20`)。

## 5. EOS は終了シーケンス完了のワンショット [解析]

**EOS は「STOP アドレスに一致した瞬間」に立つのではない。**

```
STOP 一致
  → 保持ラッチ [解除は START アドレスのロードのみ]
  → 実メモリ読み転送が起きるのを待つ
  → 多段の遅延
  → 終了検出条件の成立
  → EOS のワンショット (立ち上がり検出)
```

固定遅延はおよそ 10 マイクロステート分 + 実メモリ転送待ちである。

### 帰結 1: BRDY の復帰と EOS の発生は同じイベント

終端に到達したあと、さらに `$08` を叩くと**両方が同時に動く**。
[04_data-register.md](04_data-register.md) §3 の「BRDY の復帰」と、この EOS は同一の事象である。

### 帰結 2: EOS はエッジトリガである

すでに再ディスパッチ待ちで居座っている状態でラッチを吐き出し直しても、**EOS は出ない。**

これは重要な性質で、経路に当たらないモード (例: `$20` のまま write) で
**EOS が連発しない**ことと、**BRDY が 0 に張り付く**ことが、
**同じ 1 つの条件から出ている**ことを意味する。

### 帰結 3: LIMIT は EOS に一切つながらない

LIMIT の一致はアドレスカウンタの 0 折り返しをゲートするだけで、
ステータスには何の変化も起こさない [解析]。

## 6. REPEAT 時も EOS は保持される — 自動クリアはされない [実測]

**REPEAT 時も非 REPEAT 時も、EOS は立てたまま保持される。自動クリアはされない。**

REPEAT 再生を 4 ループ (36341 半クロック) 回した実測で、EOS は立ち上がり 1 回・
立ち下がり 0 回で、一度も落ちなかった。CPU からのステータスポーリングでも、
最初の終端以降は全回数で捕捉できた。

> **誤読しやすい点**: 実機のログを見ると REPEAT 再生中に EOS が消えているように見えることがある。
> これは自動クリアの証拠ではない。測定側のドライバが 1 バイトごとに
> `$10 = $80` (IRQ RESET) を挟んでいるため、**測定ハーネス自身が消している**だけである。

REPEAT 再生はそもそも終わらないので、**マニュアル p.54 の「EOS が立つまで待機」という手順は
非 REPEAT (`$A0`) 側のものと読むべきである** ([07_manual-vs-hardware.md](07_manual-vs-hardware.md))。

この結論には留保がある → [09_open-questions.md](09_open-questions.md)。

## 7. STATUS1 の D6 はマニュアルの「未使用」に反して値を返す [実測]

マニュアル p.52 は D6 を未使用 (常に 0) としているが、**実機は値を返す。**

全 21 種類の実機ログから、`$08` アクセス直後のステータスリードを抽出して集計した結果:

| 条件 | 件数 | 結果 |
|---|---|---|
| `$08` の**メモリリード直後** | 6848 件 | **D6 = 直前に読み出したデータの bit6** (100% 一致、破れ 0 件) |
| 再生中の `$08` リード直後 | 96 件 | **同じ** (100% 一致) |
| `$08` の**メモリライト後** | 2534 件 | **D6 = 0** (全件) |

**ライト時も直前にバスへ出ていたのは書き込みデータ**なので、
バス容量の残留 (フローティング) では read / write のこの非対称を説明できない。
**読み出しデータラッチが D6 を駆動している**と見るのが自然である [推定]。

**フラグとしての意味は無い。** ただし実機のログと突き合わせる限り必ず現れるので、
比較するときは D6 をマスクして見るとよい。

## 8. BUSY [解析]

BUSY は 5bit カウンタのオーバーフローで解除される。カウント数は 32。

| プリスケーラ | BUSY の長さ |
|---|---|
| ÷6 (リセット時の初期値) | **192 マスタクロック** |
| ÷3 | 96 マスタクロック |
| ÷2 | 64 マスタクロック |

→ **`32 × プリスケール` マスタクロック**。

マニュアルの記述との違いが 2 点ある。

- **トリガは A0=1 のデータ書き込みすべてである。** A1 は見ていない。
  FM 音源部だけでなく **SSG / リズム / ADPCM-B / `$10` への書き込みでも立つ。**
  アドレス書き込み (A0=0) では立たない。
- **走行中の再書き込みでカウンタをリロードしない。**
  連続書き込みでは 2 発目以降の BUSY が短くなる。

BUSY だけはステータスラッチを通らず、常にライブの値が読める。

## 9. ステータスリード中はラッチが凍る [解析]

RD ストローブが L の間、**内部フラグ → ステータスラッチの転送が凍る**。
リードサイクル中にフラグが変化してもバス上でグリッチしないための構造である。

- フラグ自体は裏で更新され続けるので、**情報は失われない** (1 リード分遅れて見えるだけ)。
- 条件が AND なのでラッチ群は共有されており、**STATUS0 のリードでも STATUS1 側が凍る。**
- IRQ 出力もこのラッチ由来なので、ステータスリード中は凍る。BUSY だけはライブ。

バスサイクルを瞬時のイベントとして扱うエミュレータでは、この構造は表現できない。
実害は極小である。

## 10. ZERO [解析]

**有効なのは A/D 変換モード中だけ**である
(`$01` D3 = SAMPLE、または REC && START)。それ以外のモードでは強制的に 0 になるので、
**通常の再生やメモリアクセスで ZERO が立つことはない。**

副作用として、このモード中は FM 側の LFO カウンタが ZERO の計時に流用される。

カウンタ幅は 16384 FM サンプルで、8MHz / プリスケール ÷6 なら **約 295ms** になる。
マニュアルの「290msec」と整合しており、**この数字は信頼できる。**

無音判定の実体は、内蔵 A/D コンバータ出力の上位 5bit がゼロ近傍かどうかである。

> **極性はマニュアルと食い違っている。[未確定]**
> 構造どおりに読むと「無音の間カウンタが 0 にリセットされ、**有音が継続したときに立つ**」
> という、マニュアルの「無音状態が続く時」とは逆の論理になる。
> どちらが誤りか断定できていない → [09_open-questions.md](09_open-questions.md)。

## 11. まとめ — 実装時に効く 6 点

1. **PCM BUSY を再生終了の判定に使わない。** START ビットの読み返しでしかない。
2. **BRDY はレベル信号。** 「レディでない期間」を表現できる必要がある。
3. **EOS は STOP 一致の瞬間ではなく、終了シーケンス完了のエッジ。**
4. **マスクはイベントを破壊する。** 読み出し時に隠すのではない。
5. **`$10` D7 は EOS / BRDY / ZERO / TA / TB をクリアし、PCM BUSY には触れない。**
6. **リセット直後は `$10 = 0x1C`** なので、EOS / BRDY / ZERO はマスクされた状態で始まる。
