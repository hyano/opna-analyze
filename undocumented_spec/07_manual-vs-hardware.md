# アプリケーションマニュアルと実機仕様の違い

一次資料はヤマハ株式会社「YM2608 OPNA アプリケーションマニュアル」(全 67 ページ)。
ここでは、そのマニュアルの記述と実機の挙動が食い違う箇所、
および**記述どおりであることを確認できた箇所**を一覧にする。

ページ番号はマニュアルのもの。根拠ラベルの意味は [01_overview.md](01_overview.md) を参照。

## 2. p.52 D5 (PCM BUSY) — 「実行中」と読んではいけない

マニュアルは PCM BUSY を「ADPCM 音声/合成の実行中 "1"」と説明している。
しかし実機では、これは **`$00` の D7 (START ビット) をラッチしただけの値**である [実測]。

- **EOS が立っても落ちない。**
- **RESET ビット (`$00` D0) を入れても落ちない。**
- **`$10` の IRQ RESET も PCM BUSY には触れない。**

つまり「再生が続いている間」ではなく **「START ビットが立っている間」**と読むべきである。

> **実用上の帰結**: 「PCM BUSY が落ちるのを待つ」ドライバは実機では返ってこない。
> 再生の終了を知るには EOS を見ること。

→ [06_status-flags.md](06_status-flags.md) §3

## 3. p.52 D6 — 「未使用」だが値が出る

マニュアルは D6 を未使用としているが、実機は値を返す [実測]。

- **`$08` のメモリリード直後**のステータスリードでは、
  **直前に読み出したデータの bit6** がそのまま D6 に出る (6848 件で 100% 一致)。
- **`$08` のメモリライト後**は D6 は常に 0 (2534 件すべて)。
- **再生中の `$08` リードでも同じ**ことが成り立つ (96 件で 100% 一致)。

ライト時も直前のバス値は書き込みデータなので、バス容量の残留では
read / write のこの非対称を説明できない。読み出しデータラッチが D6 を駆動していると
見るのが自然である [推定]。

**フラグとしての意味は無い**ので、エミュレータで再現する優先度は低い。
ただし実機のログと突き合わせるときは、**必ず現れるので D6 をマスクして比較すること。**

→ [06_status-flags.md](06_status-flags.md) §7

## 4. p.52 D7 (BUSY) — FM 専用ではない

マニュアルは BUSY を「FM 音源部のレジスタにのみ有効」としているが、実機のトリガは
**A0=1 のデータ書き込みすべて**である [解析]。A1 は見ていないので、
SSG / リズム / ADPCM-B / `$10` への書き込みでも BUSY は立つ。
アドレス書き込み (A0=0) では立たない。

さらに **走行中の再書き込みではカウンタをリロードしない**ため、
連続書き込みでは 2 発目以降の BUSY が短くなる。

長さそのもの (`32 × プリスケール` マスタクロック) は仕様と一致している。

→ [06_status-flags.md](06_status-flags.md) §8

## 5. p.52 D4 (ZERO) — 極性が逆に読める [未確定]

マニュアルは「ADPCM 音声分析中、290msec 以上、**無音**状態が続く時 "1"」と書いている。
しかし構造どおりに読むと、**無音の間はカウンタが 0 にリセットされ、
有音が継続したときにカウンタがオーバーフローして立つ**という逆の論理になる。

考えられるのは次の 2 つで、**どちらとも断定できない。**

- マニュアルの日本語が誤解を招く書き方になっている
- 解析モデルの内蔵 A/D 変換部の極性が不正確 (この部分には既知の不確かさがある)

なお **290msec というカウンタ幅そのものは実機と一致している** (16384 FM サンプル ≒ 295ms)。
こちらは信頼できる。

→ [09_open-questions.md](09_open-questions.md)

## 6. p.54 音声合成の手順 — REPEAT では EOS を待てない

p.54 の手順表は `$00` に `$A0` / `$B0` を書いて EOS が立つまで待つ、と読める。
しかし **REPEAT (`$B0`) では EOS は立てたまま保持され、再生も終わらない** [実測]。

**この待機は非 REPEAT (`$A0`) 側の手順である。**

→ [06_status-flags.md](06_status-flags.md) §6

## 7. p.48 分解能 — 書きの粒度は ROM ビットを見ない

マニュアル p.48 はメモリ種別ごとの分解能 (×1bit DRAM = 4byte、ROM/×8bit = 32byte) を
記載しているが、**読みと書きで効き方が違う**ことには触れていない。

実機では、アドレスカウンタの歩進頻度を決めるのは **RAMTYPE (`$01` D1) だけ**で、
ROM ビット (`$01` D0) は関与しない [解析]。結果として:

- **ROM を指定した状態での書き込みは bit 単位になる** (1 バイトあたり 8 回の WE パルス)。
  ROM への書き込み自体は無意味だが、`$08` へ書けばチップはそう振る舞う。
- 読み出しのディスパッチだけは ROM ビットを見る。

→ [03_address.md](03_address.md) §7

## 8. p.53 / p.54 手順表 — `$01 = $03` は定義されていない

手順表が `$01` に挙げるのは、書き込み側 (音声分析) が `$00` / `$02`、
読み出し側 (音声合成) が `$40`〜`$42` だけである。
p.53 の RAM/ROM-READ も `$00`〜`$02` と範囲で書かれており `$03` を含まない。

実機では **`$03` (ROM かつ RAMTYPE=1) はどの読み出し経路にも当たらず、
外部メモリに一切アクセスしない** [解析]。書き込みだけは byte 単位で通常どおり動く。

**つまりマニュアル側もこの設定を定義していないと読める。**
「マニュアルに書かれていない設定は、チップ側にも経路が無い」という形で
両者が符合している例である。

→ [03_address.md](03_address.md) §7

## 9. マニュアルの記述が正しいことを確認できた項目

食い違いばかりを並べると誤解を招くので、**裏付けが取れた記述**も挙げておく。
マニュアルの記述は、以下の点では信頼してよい。

| 箇所 | 記述 | 確認内容 |
|---|---|---|
| p.53 RAM/ROM-READ の注記 | 「最後の 2 データ分はフラグが立たないので、フラグに関係なく読み出す事」 | **正しい。** 機構まで説明が付いている — 先読み 2 段が STOP 到達後もラッチに残り、メモリサイクルが止まって BRDY が復帰しないため ([04_data-register.md](04_data-register.md) §3) |
| p.53 / p.55 ダミーリード | READ で 2 回、音声分析で 1 回 | **正しい。** 回数は経路のラッチ段数そのもの。メモリ種別によって変わらない |
| p.48 アドレス構成 | BANK (3bit) + CAS (9bit) + RAS (9bit) = 21bit | **正しい。** 実効アドレス幅も 21bit で、内部の比較器も 9+9+3bit の 3 相構成になっている |
| p.50 LIMIT | 到達すると 0 番地に戻る。STOP 以上の値にすること | **正しい。** 戻り先は 0 番地であって START ではない。LIMIT < STOP にすると STOP に到達せず EOS が立たない |
| p.51 `$10` のマスク | "1" でそのフラグを**発生させない** | **正しい。** 「読み出し時に隠す」ではなく「発生時に破壊する」であり、この表現は正確 |
| p.51 `$10` の初期値 | リセット後 D4/D3/D2 = 1 (`0x1C`) | **正しい** |
| p.46 RESET | 音声合成を停止して初期状態に戻す | **正しい。** RESET は STOP 一致の保持ラッチを強制セットするので、次のアクセスは必ず START ロードを伴う |
| p.46 スタートのかかり方 | 外部メモリアクセス時は START ビット、CPU 管理メモリでは `$08` の READ/WRITE でスタート | **正しい。** START アドレスのロードもこのタイミングで起きる |
| p.52 ZERO の 290msec | 290msec 以上 | **正しい** (16384 FM サンプル ≒ 295ms)。極性だけが未確定 |
| p.53-56 の 6 つの手順表 | RAM-WRITE / RAM・ROM-READ / 音声分析・合成 (外部メモリ / CPU) | **チップ内部の転送経路の分類とそのまま 1 対 1 に対応する。** 表の区切り方がハードウェアの構成を反映している ([02_internals.md](02_internals.md) §7) |
