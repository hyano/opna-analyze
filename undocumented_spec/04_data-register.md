# データレジスタ `$08` 経由のメモリ読み書きの実機仕様

CPU から外部メモリを読み書きするとき、データは `$08` を通る。
ここではその挙動を、[02_internals.md](02_internals.md) §3 のラッチ列から説明する。

**この章の内容はほぼすべて「4 段のバイトラッチ直列」という 1 つの構造から出てくる。**
個別の仕様として覚える必要はない。

根拠ラベルの意味は [01_overview.md](01_overview.md) を参照。

---

## 1. マニュアルの手順 (p.53-55)

| 手順 | `$00` | `$08` アクセス | ダミーリード |
|---|---|---|---|
| RAM-WRITE (CPU→OPNA→RAM) | `$60` (REC + MEMDATA) | write | — |
| RAM/ROM-READ (外部メモリ→OPNA→CPU) | `$20` (MEMDATA) | read | **最初の 2 回** |
| 音声分析 (OPNA→CPU) | `$C8` (START + REC + SPOFF) | read | **最初の 1 回** |
| 音声合成 (CPU→OPNA) | `$80` (START) | write | — |

RAM/ROM-READ には次の注記がある。

> 『最後の 2 データ分はフラグが立たないので、フラグに関係なく読み出す事。』

**この注記は正しい。** 以下、ダミーリードの回数と「最後の 2 データ」の両方が、
同じ 1 つの構造から出てくることを示す。

---

## 2. ダミーリードの回数 = 経路のラッチ段数

先読み段を前進させているのは、**メモリフェッチの完了ではなく CPU の `$08` アクセスそのもの**である
[解析]。1 回のアクセスにつき 1 段しか進まない。したがって:

| 経路 | 段数 | ダミーリード |
|---|---|---|
| 外部メモリ → CPU | L2 → L3 の 2 段 | **2 回** |
| エンコーダ → CPU | L4 → L3 の 1 段 | **1 回** |
| CPU → 外部メモリ | L3 は CPU の write サイクルで直接書かれる | **不要** |
| CPU → デコーダ | L3 → L4 の 1 段 | **不要** |

マニュアル p.53 の「2 回」と p.55 の「1 回」は、この段数そのものである。

> **ダミーリードの回数はメモリ種別によって変わらない。** [解析]
> ×1bit DRAM でも先読み段は L2 / L3 の 2 段で、L2 の埋め方が
> 「ビット挿入 8 回」か「バイト転送 1 回」かが違うだけである。

## 3. 末尾 2 データで BRDY が立たない機構

STOP に到達すると保持ラッチが立ち、読み出しループの分岐がアイドルへ戻る
([03_address.md](03_address.md) §4)。以後メモリサイクルが一切走らないので、
**BRDY の「レディである」条件が恒久的に 0 に張り付く** [解析]。

一方、L2 と L3 にはまだ 2 バイト残っているので、データ自体は読み出せる。

```
先読み段数 2  =  メモリサイクルを伴わない末尾リードの回数 2
```

**ダミーリードの回数と、末尾でフラグが立たないデータ数が一致するのは偶然ではない。**
どちらも同じ 2 段の先読みバッファを、入口側から見るか出口側から見るかの違いである。

BRDY を復帰させるには、終端に到達したあとさらに `$08` をアクセスして
終了シーケンスを完了させる必要がある。そして:

> **BRDY の復帰と EOS の発生は、同じ 1 つのイベントである** [解析]。

## 4. ダミーリードが返すのは「前の操作の残留」

L2 / L3 は転送のたびに上書きされるだけで、**クリアされない**。
したがってダミーリードで出てくるのは、**直前の操作でそこに残っていた 2 バイト**である [実測]。

- **READ を途中で止めた場合**: 次のダミーリードは、そのとき先読みしていた 2 バイト
- **WRITE の直後**: 次のダミーリードは、最後に書いたデータが 2 バイト
- **再生 (`$A0`) の直後**: **再生が最後にフェッチしたデータ**が出る

3 番目は、**再生経路と CPU 読み出し経路が同じラッチ列を共有している**ことの直接の証拠である
([05_playback.md](05_playback.md) にも同じ観測がある)。

> エミュレータが「次に読むべきデータ」を先読みして返す実装になっていると、
> この 3 つがすべて実機と食い違う ([08_ymfm-differences.md](08_ymfm-differences.md))。

---

## 5. `$08` の read / write にはモード判定が入らない

**`$08` の read は L3 の現在値を無条件に返し、write は L3 を無条件に上書きする** [解析]。
「今このモードだからアクセスできない」というガードは存在しない。

これは実機の挙動を理解するうえで決定的に重要である。次節の「経路に当たらない設定」も、
再生中の `$08` read が値を返すことも ([05_playback.md](05_playback.md))、
すべてこの 1 点から出ている。

## 6. 経路に当たらない設定では「ラッチだけ動いて止まる」

REC と MEMDATA の組み合わせが [02_internals.md](02_internals.md) §7 の
どの経路にも当たらない場合、**外部メモリのシーケンサは一切起動しない。
しかし先読み段とラッチ列だけは進む。** この中間状態は CPU から観測できる [実測]。

| 設定 | 実機の挙動 |
|---|---|
| `$00 = $60` (REC=1 / MEMDATA=1) で `$08` を **read** | **外部メモリアクセスが一度も起きない。** 1 バイト目はラッチの残留値が返り、**2 バイト目以降はステータスが `0x00` (BRDY=0) に張り付く**。STOP を超えて読んでも **EOS は立たない**。REPEAT の有無でも変わらない |
| `$00 = $20` (REC=0 / MEMDATA=1) で `$08` に **write** | **メモリは変化しない。** 2 バイト目以降 BRDY=0 に張り付く。その後読み出すと、ラッチの 1 バイト目だけが最後に書いた値、2 バイト目は元の残留値のまま |

つまり **REC ビット (`$00` D6) は転送方向のゲートとして実際に効いている。**
方向が食い違うと、チップは「エラー」を返すのではなく**静かに止まる**。

### 経路に当たる設定へ戻したとき

`$60` で read している途中に `$20` へ戻すと、**そこからメモリリードが始まり、
切替後の最初の `$08` で外部メモリアクセスが 2 回続けて出る** [実測]。
空になっていた先読み 2 段を一度に埋め直している。
切替が 1 バイト目の直後なら、以降は通常の READ シーケンスとバイト数まで一致する。

構造上は「アイドルを抜けるディスパッチが、通常のハンドシェイクとは独立に
1 バイトのメモリサイクルを走らせるため」である [解析]。
普段はこれがハンドシェイク側と重なるので 1 バイトしか動かないが、
レディが落ちたままの状態から復帰するときだけ 2 バイトが続けて動く。

### BRDY の「張り付き」が意味すること

ここで観測される「2 バイト目以降 BRDY=0」は、
**BRDY がイベントパルスではなくレベル信号である**ことを実機で直接示している。
イベントラッチなら「一度立って消える」になるはずのところが、
「そもそも立たない状態が続く」になっている ([06_status-flags.md](06_status-flags.md))。

同じ 1 つの条件から、**EOS が連発しないこと**も出る。
EOS はエッジトリガなので、再ディスパッチ待ちで居座っている状態では
ラッチを吐き出し直しても発生しない。

## 7. モードを切り替えてもシーケンサは切り替わらない

**START / STOP を書き換えずに `$00` のモードだけを変えても、
メモリ I/F シーケンサは元のバンクに居座り続ける** [解析]。
バンクのディスパッチはアイドルを抜けるときにしか起きず、
それは STOP 到達か RESET ビット / IC でしか発生しないためである
([02_internals.md](02_internals.md) §5)。

| 切り替え | 実測結果 |
|---|---|
| write (`$60`) → read (`$20`) | **書き込みバンクに居座る。** アドレスカウンタはリロードされず継続する。「read」アクセスは直前に書いたバイトをエコーし続け、**そのアクセスごとに同じ値を次々の番地へコミットしてメモリを前方へ破壊する** |
| read (`$20`) → write (`$60`) | **読み出しバンクに居座る。** このバンクには WE をアサートする段が無いので write はメモリに届かない。CPU 可視ラッチ (L3) だけは無条件に更新される |
| write 実行中に単発の `$08` read | 先読み段のトリガが read / write を区別しないので、この余計な read もアドレスカウンタを進め、直前バイトを再コミットする。1 バイト重複し、以降が 1 スロットずれる |
| 途中に `$00 = $00` を挟む | **これだけでは再ディスパッチは起きない** (RESET ビットや IC とは別物)。その区間の `$08` はアドレスとメモリに対して no-op になるが、L3 は無条件に上書きされる |

**方向の非対称に注意すること。**
「読みモードのまま write するとアドレスは進むがコミットされない」は片方向の話でしかない。
逆向き — 書き込みバンクに居座ったまま「read」する — では**コミットが起き続ける**。
WE のアサートが `$00` の現在値を条件にしていないためである。

> 実用上の指針: **転送の方向を変えるときは、RESET ビットを入れてから設定し直すこと。**
> `$00` のモードビットだけを書き換えても、シーケンサは前の方向のまま動き続ける。

## 8. メモリ種別ごとのアクセス回数

| メモリ | 1 バイトあたりの外部アクセス |
|---|---|
| ROM | 1 回 |
| ×8bit DRAM | 1 回 |
| ×1bit DRAM | **8 回** |

×1bit DRAM のビット組み立ては、**アドレスカウンタの下位 3bit がそのままビット位置**になる [解析]。
LSB first で 8 ビット集めて 1 バイトを構成する。

書き込みはメモリ種別によらず同じバンクに入り、ビット単位ループに入るかどうかは
RAMTYPE だけで決まる。この非対称の帰結 (ROM 指定時の書き込みが bit 単位になる等) は
[03_address.md](03_address.md) §7 を参照。

## 9. `$08` アクセスと STATUS1 の D6

`$08` から**メモリリードした直後**にステータスを読むと、
**直前に読み出したデータの bit6 が STATUS1 の D6 に現れる** [実測]。
`$08` への**メモリライト後**は D6 は常に 0 である。

マニュアル p.52 は D6 を未使用 (常に 0) としているので、これはマニュアルとの明確な食い違いである。
フラグとしての意味は無いが、実機のログと突き合わせる限り必ず現れる。
詳細は [06_status-flags.md](06_status-flags.md) を参照。

## 10. 対象外

エンコーダ経路 (音声分析) と AD/DA 変換については、
**基準となる観測データが得られていないため本ドキュメントでは扱わない。**
経路のラッチ段数だけは構造から確定しており (エンコーダ→CPU は 1 段)、
マニュアル p.55 の「ダミーリード 1 回」と整合している。
