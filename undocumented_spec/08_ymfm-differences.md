# ymfm と実機仕様の差分・精度向上の提案

エミュレータ [ymfm](https://github.com/aaronsgiles/ymfm) の ADPCM-B 実装と、
これまでの章で述べた実機仕様との差分を整理し、精度向上の方向を提案する。

**この章は提案であって、ymfm 本体への変更の記録ではない。**

根拠ラベルの意味は [01_overview.md](01_overview.md) を参照。

---

## 1. 前提

### 比較の基準

差分は **`aaronsgiles/ymfm` の `adpcm-test` ブランチ (`37d0112`) を基準**にしている。
このブランチには ADPCM-B を実機解析に合わせ込む改良がすでに積まれているため、
**`main` ブランチの ymfm は、以下に挙げる差分よりさらに実機から離れている**
([01_overview.md](01_overview.md))。

### ymfm の設計方針

ymfm の README は、目標を次のように定めている。

> The goal of these cores is not 100% digital accuracy.
> To achieve that would require full emulation of the pipelines, which would make the code
> extremely difficult to comprehend.
>
> Instead, the main goals are:
> 1. Extremely high (audibly indistinguishable) accuracy
> 2. Reasonable performance
> 3. Clean design with readable code
> 4. Clear documentation of the various chips

**本章の提案はこの 4 点の範囲内に収める。** 具体的には:

- **パイプラインのサイクル単位の再現は提案しない。** マイクロシーケンサのステート数や
  DRAM リフレッシュの位相は、CPU から観測できる転送データ列に一切現れないので
  ([02_internals.md](02_internals.md) §6)、模擬する必要が無い。
- **ファミリ共通コード (`ymfm_fm.ipp` 等) には触れない。** 提案はすべて
  `adpcm_b_channel` と `ym2608` に閉じるので、他のチップへの影響は無い。
- **「可読性を犠牲にして精度を取る」提案はしない。** 後述するとおり、
  主要な提案はむしろ既存のハックを削る方向に働く。

## 3. 差分の由来は 5 つの構造欠落に集約できる

上の 15 項目は独立した 15 個のバグではない。**そのほとんどは、
実機が持っていて ymfm が持っていない 5 つの構造から出ている。**
個別に値を合わせ込むのではなく、この 5 つを埋める方が結果的に簡潔になる。

### A. CPU から見えるラッチが独立していない

**実機**: `$08` の read / write は、モード判定を一切通さずに L3 を読み書きする
([04_data-register.md](04_data-register.md) §5)。

**ymfm**: `read()` が `!execute() && !record() && external()` を要求し、
条件を外れると **0 を返す**。「常時読める CPU 可視ラッチ」に相当するものが無い。

→ 差分 **#1**, **#2** (read 側)

### B. 先読み 2 段の残留バッファがない

**実機**: L1 / L2 / L3 はクリアされず残留する。段を進めるのはフェッチの完了ではなく
**`$08` アクセスそのもの**で、read / write を区別しない
([02_internals.md](02_internals.md) §3)。

**ymfm**: `m_buffer` + `m_nibbles` の単一ニブル FIFO。初回だけ 2 バイト分パディングするが、
以降は `request_data()` が**次に読むべきデータ**を先読みして返す。

→ 差分 **#3**、および REPEAT 折り返しのダミーリード回数

### C. 再生経路と CPU 経路がバッファを共有していない

**実機**: 両方が同じ L1→L2→L3 を通り、同じハンドシェイクで次バイトを要求する。
シーケンサのループ分岐は再生と CPU アクセスを区別しない
([05_playback.md](05_playback.md) §5)。

**ymfm**: バッファ自体は `request_data()` 経由で共有しているが、
A のガードによって再生中は CPU 側の経路が切れる。

→ 差分 **#4**、および #14 の論点

### D. REC / MEMDATA のモードデコードが転送経路に効いていない

**実機**: `$00` の D5/D6/D7 と `$01` から転送経路をデコードする。
**経路に当たらない組み合わせでは、メモリサイクルは起きないが先読み段だけ 1 段進み、
L3 は CPU 値で上書きされる**という中間状態になる ([04_data-register.md](04_data-register.md) §6)。

**ymfm**: `write()` は `execute()` / `external() && record()` / それ以外の 3 分岐のみ、
`read()` は `record()` を弾いて 0 を返す。**この中間状態が存在しない。**

→ 差分 **#2** (最大の影響。実機ログとの比較で最も多く外れる)

### E. BRDY がレベル信号でなく、STOP 到達の保持ラッチもない

**実機**: BRDY は「レディである状態」を表すレベル信号。
STOP 一致は自己保持ラッチで、解除は START アドレスのロード時のみ。
このラッチが立つとシーケンサがアイドルへ落ち、
**①メモリサイクル停止 → BRDY 恒久 0** と
**②L2 / L3 の残り 2 バイトは BRDY 無しで読める**を**同時に**説明する
([04_data-register.md](04_data-register.md) §3)。

**ymfm**: BRDY は `read_ram()` / `write_ram()` / `request_data()` の成功時にセットする
イベント式で、「レディでない期間」を表現できない。STOP 到達の保持は
`STATUS_INTERNAL_DRAIN` (read 用) と `STATUS_INTERNAL_SUPPRESS_WRITE` (write 用) に
パス別に分解されており、`advance_address()` は毎回 `==` 比較するだけである。

→ 差分 **#7**, **#8**、および #2 の BRDY 張り付き側

## 4. 提案

### 4.1 A / C / D をまとめて解く — `$08` アクセスを 1 本の経路に集約する

**最優先。** `#1` `#2` `#4` が同時に解ける。

現在は `read()` / `write()` / `request_data()` / `read_ram()` / `write_ram()` に
分散している条件判定を、次の形に置き換える。

- **`$08` の read / write を 1 つの関数にまとめる。**
  この関数は無条件に CPU 可視ラッチを読み書きする (構造 A)。
- **転送バンクを列挙値 1 つで持つ** (IDLE / WRITE / READ / PLAY)。
  **バンクの選択はアイドルのときだけ行い**、`$00` / `$01` からモードをデコードする (構造 D)。
  STOP 到達でアイドルへ戻る。
- **再生も CPU アクセスも同じラッチ列と同じハンドシェイクを使う** (構造 C)。

追加される状態は次の程度で、**サイクル単位の状態機械にはならない**。

| 追加する状態 | 型 | 意味 |
|---|---|---|
| 先読みラッチ 2 個 + CPU 可視ラッチ 1 個 + デコーダ側シフタ 1 個 | `uint8_t` ×4 | L1 / L2 / L3 / L4 |
| 転送バンク | 列挙値 1 個 | IDLE / WRITE / READ / PLAY |
| 転送要求 / レディ | `bool` ×2 | ハンドシェイク |

実行時コストは `$08` アクセス 1 回と 1 バイトフェッチあたり定数で、
現在のニブル FIFO の操作と同程度である。

> **可読性への影響**: 分岐条件の集合が、
> 「ハードウェアのバンクとラッチ列」という**名前の付いた構造**に置き換わる。
> `STATUS_INTERNAL_DRAIN` / `STATUS_INTERNAL_SUPPRESS_WRITE` のような
> パス別のフラグは不要になるので、**むしろ簡潔になる方向**である。

### 4.2 ニブル FIFO をバイトラッチ列に置き換える

`#3` `#6` が解ける。

現在の `m_buffer` / `m_nibbles` は、実機のラッチ列を「ニブル数」という 1 つの量に
畳んだ抽象である。この抽象では表現できないものが 2 つある。

- **ダミーリードの残留** (どのバイトがどの段に残っているか)
- **末尾で失われるのが「1 バイト」であって「3 ニブル」ではないこと**

バイトラッチ列にすると、`clock()` にある `consume_nibbles(3)` — 末尾 3 ニブルを
まとめて捨てるハック — が不要になる。実機の構造は次の 3 点で、これを入れると
「フェッチ 32 回」「EOS は 61 ニブル後」「停止後のダミーリード 2 バイトが連番」
「再生完了後のダミーリードは最終バイトが 2 回」が**同時に**成立する。

1. **L3 は L4 の 1 バイト先を保持するステージング段**で、
   `L4 ← L3` と `L3 ← L2` が同時に起きる
2. **外部フェッチは、そのバイトの 1 ニブル目をデコードした直後に走る**
   (= 開始時 2 バイト先読み、1 ニブル後に 3 バイト目)
3. **終端アドレスに当たったフェッチでバンクがアイドルに落ちる**ので、
   次に L3 から渡されるバイトが最後になる。EOS はそのバイトを渡した時点で立ち、
   残り 2 ニブルはそのままデコードされる

> **注意**: L3 を L4 と同じ値にすると、上の 4 つのうち後ろ 2 つが両立しない。
> L3 が「1 バイト先」であることが必要である。

### 4.3 BRDY をレベル信号にする — ただし `$110` D7 とセットで

`#7` が解ける。ただし**単独で入れてはいけない。**

- `adpcm_b_channel` に BRDY のレベルを表す `bool` を持ち、`status()` が読み出しのたびに
  これを OR する。
- **同時に `$110` D7 (IRQ RESET) が BRDY をクリアするようにする。**
  レベルにした以上、これが無いと BRDY=0 が一度も観測できなくなる。

`$110` D7 については、**PCM BUSY をクリアしないようにする**変更も対で必要である
(`#12`)。実機の IRQ RESET は EOS / BRDY / ZERO / TA / TB のみを対象とする
([06_status-flags.md](06_status-flags.md) §2)。

### 4.4 STOP 到達を保持ラッチにする

`#8` `#5` が解ける。

`advance_address()` の毎回比較に加えて、**「終端に到達した」ことを保持する 1bit** を持つ。

- 解除は **START アドレスのロード時のみ**
- **`$00` の RESET ビットと IC は、逆にこれを強制セットする**

これに 4.1 のバンクを組み合わせると、`#5` (REPEAT=1 での書き込みの破綻) が
**特別扱いなしで**再現される。実機でこれが起きる理由は、
**REPEAT の折り返しが書き込み中であっても常に READ バンクで再ディスパッチされる**ことにある
([03_address.md](03_address.md) §8)。読み出しバンクには WE を出す段が無く、
バンクはアイドルでないので再ディスパッチもできないため、RESET まで抜けられない。

同じ 1 つの構造から、REPEAT 読み出しの折り返しでダミーリードが 1 回になることも出る。

### 4.5 EOS をエッジトリガの終了シーケンスとして扱う

`#6` の EOS 側が解ける。

現在は `write_ram()` が `advance_address()` の返り値を見て**その場**で EOS を立てるため、
実機の多段遅延と食い違う (実機は 63 バイト目、ymfm は 64 バイト目)。

実機の構造は次のとおりである。

- STOP 一致の保持ラッチ → 実転送待ち → 遅延 → **立ち上がり検出で EOS ワンショット**
- **BRDY の復帰と EOS の発生は同じ 1 つのイベント**
- **エッジトリガなので、居座っている状態でラッチを吐き出し直しても EOS は出ない**

最後の性質が重要で、経路に当たらないモードで **EOS が連発しない**ことと、
**BRDY が 0 に張り付く**ことが、同じ 1 つの条件から出る。
別々のガードを足す必要は無い。

### 4.6 メモリ種別のゲーティングとアドレス幅

`#9` `#10`。どちらも小さな変更で済む。

- **`address_shift()` を転送方向で分岐させる。**
  書き込み方向では `dram_8bit()` **だけ**を見る (ROM 指定時に 4byte ブロックになる)。
  読み・再生では従来どおり `rom_ram() || dram_8bit()` を見る。
- **`rom_ram() && dram_8bit()` のときに読み・再生の経路を塞ぐ判定を 1 つ追加し、
  READ バンクの選択・再生のディスパッチ・デコーダの進行をゲートする。**
  書き込みは通す。この READ 側は 4.1 の「経路に当たらない」既存パスへ合流させれば、
  BRDY の張り付き方も自動的に揃う。
- **`advance_address()` の折り返しを `& 0xffffff` から
  `& ((1 << (16 + address_shift())) - 1)` へ変える** (ROM/×8bit = 21bit、×1bit DRAM = 18bit)。

> **他チップへの影響が無いことの確認**: YM2610 は `m_address_shift` が 8 固定で、
> `address_shift()` はその値をそのまま返す。したがって折り返しは
> `(1 << 24) - 1` となり、**従来の `& 0xffffff` と同値**である。

### 4.7 マスクをイベント破壊的にする

`#11`。

実機のマスクは常時評価のレベル信号だが、**ymfm 側の観測点はステータスリードと IRQ しかない。**
したがって「**マスクの効き方が変わる瞬間**」と「**読み出しの瞬間**」に破壊すれば等価になる。
常時評価は不要である。

具体的には、マスク対象のフラグを破壊する処理を 1 つ用意し、次の 2 か所から呼ぶ。

1. **`$110` D7=0 の書き込み時** — 旧マスクで破壊 → マスク値を更新 → 新マスクで破壊。
   前者が「マスク中に起きたイベントが解除後に顔を出す」のを防ぎ (これが差分の本体)、
   後者がマスクを立てた瞬間に既存フラグを消す。
2. **`read_status_hi()` の先頭。**

対象は TA / TB と EOS / BRDY。ZERO は ymfm が一度も立てないので対象外。
**読み出し時のマスクは残すこと** — BRDY をレベルにした場合、
マスク中に 0 を返すには読み出し時マスクが必要になる。

なお ymfm の `m_flag_control` の初期値 `0x1c` は実機と一致しており、
**電源投入直後は EOS / BRDY / ZERO がマスクされた状態**から始まる。

## 5. 優先度

| 優先度 | 項目 | 理由 |
|---|---|---|
| **1** | 4.1 (A / C / D)、4.2 (バイトラッチ列) | 音への影響が最も大きく、[実測] で裏付けられている。既存のハックが減る |
| **2** | 4.3 (BRDY レベル + `$110` D7)、4.4 (STOP 保持ラッチ)、4.5 (EOS のエッジ化) | [実測] 由来。4.1 の構造が入っていれば自然に収まる |
| **3** | 4.6 (メモリ種別・アドレス幅)、4.7 (マスク) | [解析] 由来で影響は小さいが、変更も小さい |
| **見送り** | `#13` (STATUS1 D6) | フラグとしての意味が無い。ログ比較時にマスクすれば足りる |
| **保留** | `#14` `#15` | 実機基準そのものが未確立 → [09_open-questions.md](09_open-questions.md) |

## 6. 見送り・対象外を勧める項目

| 項目 | 理由 |
|---|---|
| **STATUS1 D6** | フラグとしての意味が無い。再現しても音は変わらない |
| **ステータスリード中のラッチ凍結** | RD ストローブ幅の話であり、バスサイクルを瞬時のイベントとして扱う ymfm の抽象では表現できない。フラグ値が 1 リード分遅れるだけで情報は失われず、実害は極小 |
| **BUSY のリロード挙動とトリガ範囲** | ymfm は BUSY を自前で持たず `ymfm_set_busy_end()` でホストへ委ねている。ホスト側の実装に依存するため ymfm 単体では完結しない。長さ (`32 × プリスケール`) は既に一致している |
| **DRAM リフレッシュ** | CPU から観測できる転送データ列に一切現れない ([02_internals.md](02_internals.md) §6)。模擬する必要が無い |
| **エンコーダ経路 (音声分析)・AD/DA 変換・ZERO フラグ** | ymfm の**未実装機能**であって精度差ではない。加えて基準となる実機データが得られていない ([09_open-questions.md](09_open-questions.md)) |

## 7. 差が無いことを確認した項目

念のため、**実機と ymfm で差が出ないことを確認済み**の項目も挙げておく。

| 項目 | 内容 |
|---|---|
| STOP と LIMIT の同時一致 | 実機でも ymfm でも STOP が先に効く |
| LIMIT < STOP という違反設定 | どちらも LIMIT で 0 に戻って STOP に到達せず、EOS が立たないまま回り続ける |
| LIMIT とステータス | LIMIT はステータスを変化させない。ymfm も同じ |
| REPEAT 時のデコーダ状態のリセット | 実機は毎ループ完全にリセットされ、ymfm も蓄積値とステップを初期化する |
| BUSY の長さ | `32 × プリスケール` で一致 |
